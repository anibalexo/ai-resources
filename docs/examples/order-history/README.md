# Order history example

This fictional example demonstrates the [feature documentation convention](../../documentation-structure.md). No order API, application, or automated tests for it exist in this resource repository. All product paths and commands below are illustrative proposals.

Read in order:

1. [Specification](spec.md): the required behavior and acceptance ids.
2. [Technical plan](plan.md): how a hypothetical existing Python web application could implement it.
3. [Tasks](tasks.md): implementation work mapped to criteria, with checks still pending.
4. [Usage](usage.md): a draft guide that would be finalized only after implementation and verification.

The [planning workflow](../../../workflows/plan-feature.md) produces the first two documents. The [implementation workflow](../../../workflows/implement-feature.md) continues with tasks, code, tests, and the final usage guide. This example includes all four files for teaching purposes; it does not relax those workflow boundaries.
