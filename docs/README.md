# Docs

Guides, references, and notes to help understand, choose, and maintain the repository's resources.

## Organization

Save each document in Markdown with a name in `kebab-case`. Add topic folders when the amount of content justifies them.

## What to document

- Topic, purpose, and context of application.
- Enough explanations and examples to reuse what you have learned.
- Links to related resources and sources consulted.
- Reference date and version when the information depends on a tool that may change.

## Usage

Use the guides to help select or adapt resources. Check that instructions tied to specific versions are still current.

## Catalog

- [Project documentation structure](documentation-structure.md): shared paths and maintenance conventions for feature specifications, plans, tasks, and usage guides.
- [Worked examples](examples/README.md): a fictional feature connecting specification, planning, tasks, and usage documentation.
